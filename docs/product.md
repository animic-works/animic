# ゲーム仕様

## 目的

お題のイラストを見ながら、Animic内でプロンプトを入力し、NovelAIで似た画像を作る対戦ゲームです。

## 検索とSNS共有

正式な公開URLは`https://animic.party/`とします。SEOを集客手段として取り組み、サービス名や遊び方・特徴に関する検索からプロダクトを見つけられるようにします。

検索対象はトップページと一般公開する説明ページです。ルーム・参加者固有の結果・認証画面・開発環境は検索対象にしません。結果をSNSで共有できることと、検索エンジンへの掲載を許可することは別に判断します。専用の共有画面を追加する際は、公開情報の範囲と検索対象にするかを決めます。

トップページでは遊び方・採点・画像例を紹介し、内容に沿ったmeta descriptionとSNS共有用の説明文を設定します。OGP画像には白背景のロゴを使います。

## 対戦の流れ

1. 各参加者の準備状態を確認し、ホストが対戦の開始操作を行います。全員の準備完了は開始の必須条件にしません。
2. 全員に同時にお題を公開し、共通の開始時刻と生成終了時刻で対戦を開始します。
3. 各参加者は制限時間内かつ提出前であれば、複数回画像を生成できます。
4. 自分の生成履歴から好きな1枚を選んで提出します。制限時間を過ぎた未提出者には、提出できる画像があれば画像選択・提出画面を表示します。追加生成は受け付けません。提出後の変更はできません。
5. 提出画像の再現度をAIで評価し、提出速度・生成回数などと合わせて最終スコアを算出します。
6. 最終スコアで勝敗を決め、結果をSNSで共有できるようにします。

対戦への参加者は開始時に確定し、切断中の人は含めません。開始できる人数は[対象範囲](#対象範囲)に従います。

ホストは開始前に難易度・制限時間・画像選択の猶予を設定します。参加者は準備完了を示せます。再戦時もホストが開始操作を行います。

制限時間と画像選択の猶予の候補と既定値は、運営者が[管理画面](#管理画面)で決めます。候補は1〜3600秒の整数で、それぞれ5個までです。運営者が決めるまでは、制限時間60・90・120秒（既定90秒）、画像選択の猶予10・15・30秒（既定15秒）を使います。候補を変えても、進行中の対戦とルームに保存済みの条件は変わりません。ルームに保存済みの条件が候補にない場合は、その値も選択肢に表示し、そのまま開始できます。

スコアに使う生成回数は、選んだ画像が何回目の生成かではなく、提出までに成功した生成の総回数です。5回の生成に成功して2回目の画像を提出した場合も5回として扱います。画像を生成できなかった処理は数えません。

提出速度による加点は制限時間内の提出に適用します。時間切れ後の提出には速度の加点を行いません。

制限時間内にサーバーが受け付けた生成は、時間切れ後に完成しても提出する画像として選べます。未提出者は画像選択画面で生成中の状態と完成した画像を確認できます。提出済みの場合は、後から完成した画像への変更はできません。

生成終了時刻を過ぎたら、時間内に受け付けた生成処理がすべて終了した時点から、未提出者に画像を選ぶ猶予を設けます。猶予の期限を過ぎても提出しなかった人は未提出として確定し、システムが画像を代わりに選ぶことはありません。生成処理がすでに終了している場合は、生成終了時刻から猶予を数えます。

生成終了時刻を過ぎて、成功した画像も生成中の画像もない未提出者は、提出できる画像がないため、猶予を待たずに未提出として確定します。生成中だった画像が生成終了時刻の後に失敗した場合も、ほかに成功した画像がなければ、失敗した時点で確定します。ほかの人の猶予は変わりません。

1対1対戦では、片方だけが提出した場合は提出者の勝ちとします。両方が未提出の場合は勝負不成立とします。どちらも、両方の提出状態が確定した時点で決めます。未提出の画像を0点の提出画像として扱うことはありません。

両方が提出した場合は、提出画像の再現度を採点し、スコアが高い方の勝ちとします。スコアが等しい場合は引き分けとします。両方が制限時間内に提出した場合は、制限時間の終了を待たずに採点結果で勝敗を決めます。全員の提出状態が確定してから5分以内に採点が終わらない場合や、採点に失敗した場合は勝負不成立とします。

3人以上の対戦では、結果を順位で表示します。全員が未提出の場合は勝負不成立、1人だけが提出した場合は採点を待たずにその人を1位とします。2人以上が提出した場合は、最終スコアの高い順に順位を付け、同点は同じ順位とします。未提出の人と、採点に失敗した人・全員の提出状態が確定してから5分以内に採点が終わらなかった人は順位なしとし、ほかの人の順位を決めます。全員の採点ができなかった場合は勝負不成立とします。

### 採点の暫定対応と解消条件

最終スコアの計算式が決まるまで、再現度の採点結果（採点ノードが出力する`total`）をそのままスコアとし、提出速度と生成回数は加味しません。計算式を決めたらスコアの算出を置き換え、この暫定対応の記述を削除します。

## 参加方法

ルームコードは大文字英数字8文字とし、ハイフンは使いません。読み間違いを減らすため、`0`・`O`・`1`・`I`・`L`を除きます。小文字で受け取ったコードは大文字に正規化します。コードはそのままルームURLのパスに使います。アプリ内で同じルームURLのコピーとQRコード表示を提供し、トップページではルームコードを入力して参加することもできます。

ルームは参加者が集まる場所として維持し、その中で対戦を繰り返せるようにします。結果画面から同じメンバーで再戦でき、お題・生成履歴・提出・結果は対戦ごとに分けます。

### ログイン

ルームを作るには、GoogleかDiscordのアカウントでログインします。ルームURLから参加する人には、ログインを求めません。ログインした参加者は、別の端末・ブラウザでも同じアカウントなら同じ参加者として扱います。ログインせずに参加した人は、そのブラウザに保存したセッションで識別します。

ログインせずに参加していた人がログインすると、別の参加者に切り替わります。ログインする前に参加したルームの参加記録は引き継ぎません。そのため、ログイン・ログアウトの操作はルームに入る前の画面に置き、ルームの中には置きません。

### 途中参加と再接続

対戦開始後に新しくルームへ参加した人や、開始時に切断していて対戦に含まれなかった人は、進行中の対戦には加わらず、次の対戦まで待機します。その対戦に参加していた人が通信切断後に再接続した場合は、同じ参加者として元の対戦に復帰します。再接続によって残り時間・生成履歴・提出状態をリセットしません。

### ホストの退出・切断

ホストが退出操作を行った場合、接続中の参加者のうち、ルームへの参加順が最も早い人にホストを引き継ぎます。引き継ぐ相手はログインしているかどうかで区別しません。通信が切断された場合は、サーバーが切断を検知してから30秒間再接続を待ち、戻らなければ同じ条件で引き継ぎます。

引き継ぎ後に元のホストが戻っても、ホストは自動では戻しません。ホストの退出・切断によって、進行中の対戦やタイマーを停止しません。

### ルームの終了

最後の接続が切れてから30分間、ルームに復帰できます。その間に誰も戻らなければルームを閉じます。期限内に参加者が戻った場合は閉じず、再び全員が切断した時点から30分を数えます。ルームを閉じても、保存済みの対戦結果は削除しません。

## 難易度とお題

| 難易度     | お題の条件              | 位置付け |
| ---------- | ----------------------- | -------- |
| かんたん   | 白背景・1キャラクター   | 基本     |
| ふつう     | 背景あり・1キャラクター | 基本     |
| むずかしい | 背景あり・2キャラクター | Extra    |

お題画像は自前で生成し、難易度と合わせて事前に登録します。各難易度100種類程度を目安とします。画像の複雑さに加え、制限時間や生成回数などの対戦条件も難易度の設計対象です。

### お題の管理

お題は運営者が[管理画面](#管理画面)で登録し、公開・非公開を切り替えます。出題するのは公開中のお題だけで、指定した難易度の公開中のお題からランダムに1つ選びます。

- 画像はPNG・WebP・JPEG（10MB以下）から選びます。管理画面でメタデータと透過のないWebPに変換してから保存し、NovelAIの画像に残ったプロンプト（お題の答え）を配信しません。WebPに変換できないブラウザーでは登録できません。
- 管理画面で追加したお題は非公開で登録します。管理画面より前にSQLで登録したお題は公開中として扱います。
- 題名（60文字まで）・備考（1000文字まで、出典や権利のメモ）・難易度・画像はいつでも変えられ、お題を削除することもできます。進行中の対戦と保存済みの結果は、開始時に確定したお題を使うため変わりません。差し替え前の画像も、過去の結果のために配信を続けます。

## プロンプト入力

自然言語での入力を基本とし、よく使うプロンプトは選択肢から入力できるようにします。熟練者向けにDanbooruタグでの入力も扱います。

対戦画面では、入力方法を文章とタグで切り替えられます。プロンプトは、背景や画風など画像全体を書くベースの欄と、キャラクターを書くキャラの欄に分けて入力します。キャラの欄は、むずかしい（2キャラクター）でだけ2つまで増やせます。「、」や「,」で区切った語句ごとに、重みを0.1〜2.0の範囲で0.1ずつ上げ下げできます。入力方法を切り替えても、入力済みの語句は変換しません。入力候補と表現の検索は同じ表現の辞書を使い、辞書はコード内の初期データとして持ちます。管理画面で登録したよく使う表現を対戦画面の候補・検索に使う対応は、別の作業で行います。プロンプトはすべての欄を合わせて1000文字までです。

選択肢と自由入力を生成サービスの入力へ変換する方法は、生成機能の設計で定めます。

### プロンプトの暫定対応と解消条件

生成の処理をつなぐまでは、ベースとキャラの語句を順につないだ1つのプロンプト（重みは`1.2::語句::`の形、文章はタグへ変換しない）を送る前提で画面を作っています。生成機能の設計（Issue #12の残り）でキャラクターごとのプロンプトに分けるかを決めたら、組み立て（`src/features/image-generation/prompt-blocks.ts`の`assemblePrompt`）を置き換え、この記述を削除します。

選択肢（よく使う表現）は、運営者が[管理画面](#管理画面)でグループに分けて登録し、並べ替えます。表現は画面に出す表示名と、NovelAIへ送る語を持ちます。同じグループに同じ語の表現は登録できません。参加者の画面での表示は、別の作業で行います。

## 画像生成

画像はNovelAIのV5 Curatedで生成します。V5 Curatedの使用料が足りなくなった場合に備えて、運営者は[管理画面](#管理画面)でV4.5 Curatedに切り替えられます。切り替えた後にNovelAIへ送る生成から新しいモデルを使い、進行中の対戦でもモデルが変わります。使用料が足りなくなっても自動では切り替えません。

運営が決めた絵柄（アーティストタグなど）を、全員の生成に付けます。絵柄のタグはリポジトリに含めず、環境ごとに設定します。参加者のプロンプトにアーティストタグがあっても除かず、規定の絵柄と合わせて生成します。参加者はモデルと絵柄を選べません。

生成した画像は、メタデータと透過のないWebPにしてから扱います。NovelAIは画像のメタデータと透過の情報に、プロンプトと規定の絵柄を含む生成の条件を埋め込むため、そのまま配信すると相手のプロンプトを読めてしまいます。

画像生成サービスの認証情報はAnimic側で用意・管理し、利用料もAnimic側が負担します。参加者に生成サービスのアカウント連携やAPIキーの持ち込みを求めません。

## 管理画面

運営者は管理画面（`/admin`）で、お題・対戦条件の候補・よく使う表現を登録し、画像生成のモデルを切り替え、採点ワーカーを管理します。管理画面は運営者のパスワードでログインした場合だけ使えます。

お題（画像を含む）・対戦条件の候補・よく使う表現は、1つのZIPに書き出し、読み込めます。D1・R2の障害や操作ミスでデータを失ったときに戻すためと、ローカルと本番の間でデータを移すために使います。

- 読み込む前に、追加・上書きされる件数を種類ごとに表示します。
- 読み込みでは同じIDのものを上書きし、ないものを追加します。ZIPにないものは削除しません。対戦条件の候補はZIPの内容に置き換えます。
- 別の環境で書き出したZIPを読み込んだ場合も、画像は読み込んだ環境に保存し、その環境のURLで配信します。
- 採点ワーカー・採点ジョブ・対戦結果・参加者の情報・生成した画像・画像生成のモデルは含めません。

## 対象範囲

ルームには8人まで参加できます。退出していない参加者は、切断中でも人数に数えます。定員に達したルームには新しく参加できず、参加済みの人は再接続できます。ホストを含む接続中の参加者が2人以上の場合に対戦を開始でき、開始時に接続中の全員が参加します。2人の対戦は勝ち負け、3人以上の対戦は順位で結果を表示します。

現在の公開アプリは、トップページ、ルーム作成前のログイン、ルーム作成・参加時の表示名入力、ロビー、対戦中のプロンプト入力・生成履歴・画像選択と提出、結果、利用規約、プライバシーポリシーで構成します。ルーム操作・対戦の進行・提出・結果はサーバーの状態と接続します。

プロフィール、戦績保存と詳細、生成回数上限、モデル別の詳細採点の画面は、現在の公開アプリの導線に含めません。接続範囲と責務は[アーキテクチャ](architecture.md#画面とapiの構成)で定めます。

ランクマッチと複数のゲームモードは追加を検討します。独立したSNSシェア画面はMVPの後に追加する機能とします。結果をSNSに共有する要件と、専用画面を設けるかどうかは区別します。

再現度は、運営者のPCで動く採点ワーカーがComfyUIのワークフローで評価します。CCIP（同じキャラクターか）・PixAI Tagger v1.0（タグの一致）・SigLIP 2（内容）・DINOv2（画像の特徴）・Depth Anything V2（構図）の5つの指標をそれぞれ0〜100点にし、CCIP 0.35・PixAI Tagger 0.25・SigLIP 2 0.20・DINOv2 0.10・Depth 0.10の重みで平均した値を再現度（`total`）とします。どちらかの画像に人物がいない場合はCCIPを除き、残りの指標の重みで平均します。構成は[採点の設計](scoring.md)を参照してください。

## 未決定事項

- ホスト以外の退出・切断、ルームを閉じる時点で未完了の対戦の扱い。
- 生成処理が終了しない場合のタイムアウト。
- 最終スコアの計算式（指標の重み、提出速度・生成回数の加点）と、生成の失敗時の扱い。
- NovelAIの生成パラメーター（モデル以外）の提供範囲。
- 閉じたルームのコードを再利用するかどうか。
- ログインせずに参加した人がセッションを失った場合の復帰方法。
- お題画像の利用・公開に必要な権利の確認方法。
- SNS共有の方式と公開する情報・画像の範囲。
