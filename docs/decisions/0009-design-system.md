# 0009: デザイン定義とUIの実装を分離する

- 状態: 承認済み
- 決定日: 2026-10-01
- 関連: [デザイン原則](../design.md)、[アーキテクチャ](../architecture.md#デザインシステム)
- 変更するADR: [ADR 0002](0002-application-foundation.md)のUI方針

## 背景

画面や機能ごとに視覚表現を定義すると、実装者による値や状態表現の差が広がり、型・lint・CIで逸脱を検出しにくい。共通の視覚表現を定義し、ReactやHeadless UIから独立させる必要がある。

## 決定

Pandaを基盤とするUIフレームワーク非依存のデザインシステム、生成されるstyled-system、React実装をワークスペース内の独立したパッケージに分ける。Animic側でスロット名を定義し、React実装が対応するArk UIの要素へスタイルを適用する。デザインシステムを利用するReact UIは、`@animic/react`の公開Componentを組み合わせる。

具体的なデザイン定義を`packages/design-system/src/`に置き、型付きSDK・CSS・Native Specを生成する。パッケージの配布方式はこの決定に含めない。

## 理由

Pandaからデザイン定義に対応する型とCSSを生成でき、パッケージの`exports`とインポートの境界検査で利用範囲を制限できる。ReactとArkの操作実装をデザイン定義から分離することで、別のUIフレームワークへ展開する場合も同じデザイン定義を利用できる。

固有のアートワークやMotionは明示的なVisual領域で扱い、通常UIを迂回する経路にはしない。

## 影響

ワークスペース、コード生成、型検査、lint、UI状態を確認するStorybook、アクセシビリティ、画像比較を整合させる必要がある。既存画面の移行は対象と検証範囲を定めて行い、ワークスペース内のパッケージ・生成処理・検証環境の導入と画面一式の移行を同一の変更として要求しない。

## 見直す条件

依存方向、公開APIの境界、Visual領域の許可範囲、別のUIフレームワークへの対応を変更する場合は、改めて判断する。
