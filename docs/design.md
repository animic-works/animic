# デザイン原則

Animicがどう見え、どう感じられるべきかを定めます。値（色・大きさ・余白）の正はここではなく[デザインシステム](design-system.md)のコードに置き、この文書は判断の拠り所になる考え方だけを書きます。

| 文書・コード                  | 役割                    |
| ----------------------------- | ----------------------- |
| docs/design.md                | なぜそう見せるか（WHY） |
| packages/design-system        | 何で見せるか（WHAT）    |
| Panda / @animic/styled-system | どう実現するか（HOW）   |
| @animic/react・画面           | 組み合わせて使う（USE） |

## 人格

明るく、遊び心があり、すぐに始められるゲームとして振る舞います。友だちと集まって遊ぶ場の楽しさを優先し、手続きの多い管理画面のような印象を避けます。

- 方眼の地にピンク・水色・黄色を差し、描いて遊ぶ場であることを伝えます。
- 角は丸く、ボタンは丸い棒の形にします。鋭い角や細い罫線で区切りすぎません。
- 文言は短く、話しかける口調にします（例: 「ルームを作ろう」）。

## 情報の優先度

1画面で伝えることを絞り、最も大事な1つを最も目立たせます。

- 主な操作（ピンクのprimaryボタン）は1画面に1つにします。並べる副次的な操作はsecondary、目立たせない操作はghostにします。
- 勝敗・順位・残り時間など、遊びの結果と緊張感を生む情報は大きく、表示用の書体（display）で見せます。
- 補足・注記は小さく淡くし、主役の邪魔をしません。

## 色の使い方

色は意味で選び、具体的な色名では選びません（`accent.default`を選び、`pink.500`は選ばない）。

- ピンク（accent）: 主な操作・自分・ブランドの強調。多用すると主役がぼやけるため、1画面の中で強調する場所を絞ります。文字や白い文字を載せる面には`accent.default`（少し濃いピンク）を使い、ブランドの色そのもの（`accent.brand`）は文字を載せない飾りや大きな面にだけ使います。
- 赤（danger）: 取り消せない操作とエラー。ピンクと見分けられる赤にします。
- 水色（info）: フォーカス・情報。キーボード操作の輪は水色で統一します。
- 黄色（warning）: ホストなど、目印になるラベル。黄色の上の文字は黒にします。
- 緑（success）: 準備完了・保存できたなど、うまくいった状態。
- 参加者は参加順の色（player.1〜7）で見分けます。色だけに頼らず、名前と並べて示します。

## 形と面

面は奥行きの4段階（sunken・surface・raised・overlay）から選びます。新しい影や枠線の組み合わせを画面ごとに作りません。

- 画面の主役のまとまりは浮いたカード（raised）にします。
- 一覧の行・選択肢は線で区切った面（surface）にします。
- 手前に開くもの（ダイアログ・メニュー）だけをoverlayにします。

## 動き

動きは状態の変化を伝えるために使い、飾りのためには使いません。

- 現れる・消えるは短く（fast〜normal）、行きすぎずに止まる動き（standard）を基本にします。
- 弾む動き（bounce）は、成功や結果の発表など、うれしい瞬間に限ります。
- 視差効果を減らす設定（prefers-reduced-motion）では動きを止め、結果だけを見せます。
- 対戦の演出のようにその画面だけの動きは、デザインシステムに入れず機能の側で持ちます。

## 文字

- 見出しは丸ゴシック（round）、本文は読みやすいゴシック（body）、英字の小見出しは斜体の欧文（latin）にします。
- ルームコードや点数など、桁をそろえたい文字は等幅（code）にします。
- 書体はモックと同じGoogle Fonts（Dela Gothic One・Zen Maru Gothic・Zen Kaku Gothic New・Montserrat・JetBrains Mono）を`src/routes/__root.tsx`で読み込みます。読み込み方法の見直し（#14）までの暫定で、読み込めない間は端末にある書体で代わりに表示します。

## アクセシビリティ

遊びやすさの一部として扱い、見た目の調整で損なわないようにします。

- すべての入力に項目名を付け、エラーは文言で伝えます（色だけに頼らない）。
- キーボードだけで操作でき、フォーカスの位置が常に見えるようにします。
- 色は画面モックの色をそのまま使います。ピンクの地に白い文字など、文字と背景のコントラストがWCAG 2.1 AAに届かない組み合わせがあり、色の見直しは決めていません（[デザインシステム](design-system.md#まだ決めていないこと)）。押せない状態は半透明にせず、淡い色で示します。
- 指で押す要素は十分な大きさにします（ボタンのmd以上）。
