# デザインシステムの設計資料

デザインシステムの設計で得た判断材料を、次のデザインシステムでも利用できる形で残します。Animicは具体的な事例であり、その構成を他の案件へそのまま適用するためのひな形ではありません。

現在のAnimicの仕様は、既存の仕様・設計文書と実装・テストで扱います。ここでは現在値やAPI一覧を複製せず、何を比較し、何が成立せず、どの検証から判断を変えたかを扱います。

## 読み始める場所

| 目的                           | 読む場所                                                                                                                                                                                                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 今のAnimicを実装する           | [文書案内](../README.md#現在の仕様実装を調べる)、[デザインシステムの変更判断](../../CONTRIBUTING.md#デザインシステムの変更判断)、[生成・検証手順](../../CONTRIBUTING.md#デザインシステムの生成と検証)。具体的なAPI・値・検査は[実装](../../packages/)と[テスト](../../tests/design-system/) |
| 重要な決定と理由を調べる       | [ADRの一覧](../README.md#判断の理由比較検証を調べる)。設計事例を読まなくても決定を理解できるようにする                                                                                                                                                                                      |
| 判断が変わった過程を調べる     | [設計事例](#現在の設計事例)から、必要に応じて検証記録へ進む                                                                                                                                                                                                                                 |
| 次のデザインシステムを設計する | [設計ガイド](design-guide.md)から問い・選択肢・判断基準を確認し、必要な設計事例へ進む                                                                                                                                                                                                       |
| 実装や設計をレビューする       | [設計レビューガイド](review-guide.md)で適合性の確認と設計そのものの評価を分け、証拠の範囲と判断が必要な点を整理する                                                                                                                                                                         |

## 文書の種類

| 種類               | 読む目的                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| 設計ガイド         | 設計時の問い、確認する前提、選択肢、判断基準、注意点と適用条件を得る                           |
| 設計事例           | 当時の前提・比較・失敗・検証・判断変更と、変更しなかった範囲を追う                             |
| 設計レビューガイド | 適合性監査と設計そのもののレビュー、証拠の読み方、判断と実装の区別、AI利用時の判断の偏りを扱う |
| 検証記録           | 設計事例を支える入力・環境・観測結果と、その証明範囲を確認する                                 |
| 現行資料           | 現在のAnimicの要件・原則・構成・規則・API・値・手順を確認する                                  |

## 更新ルール

文書ごとの責務・更新方法・検証記録を作る条件は、[CONTRIBUTINGの文書の管理](../../CONTRIBUTING.md#文書の管理)に従います。
