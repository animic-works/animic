# フォントの責務分割の検証記録

[フォントの責務分割の設計事例](../case-studies/font-ownership.md)を支える、実装・検証の記録です。対象は2026-10-04までの判断と観測です。

## 対象時点と出所

コードと検証の観測を記録します。FO-E02〜FO-E04は2026-10-04の実装確認と契約テスト、FO-E05・FO-E06は配置変更後の再現性・ブラウザ検証です。それぞれの対象・方法・結果を分けて記載します。

契約テストはNode.js 24.21.0、Vite+ 0.3.3、Vitest 4.1.11で実行しました。対象の依存関係はPanda CSS 2.0.1、Fontsource各パッケージ5.3.0です。ブラウザ検証の環境と確認範囲はFO-E06に分けています。

実装・テストへのリンクは現在の参照先です。リンク先が変わっても、ここに記録した入力・観測結果を現行仕様へ書き換えません。

## FO-E02

**デザイン定義を参照して必要なCSSを求める実装**

**対象時点:** 2026-10-04の実装。変更前実装との比較ではありません。

**確認対象:** [Typography Token](../../../packages/design-system/src/tokens/primitive/typography.ts)、[Text Style](../../../packages/design-system/src/styles/text.ts)、[アセット対応](../../../packages/design-system/src/font-assets.ts)、[生成スクリプト](../../../scripts/generate-fonts.mjs)。

**観測結果:**

- フォント名・フォールバックフォント・太さの値はTypography Tokenにあり、各Text StyleがフォントTokenと太さTokenを参照していました。
- `font-assets.ts`の値はFontsourceパッケージ名だけで、Text Style名・用途・必要な太さの一覧を持っていませんでした。
- `fontImports()`はText Styleを走査し、参照するフォント・太さTokenとアセット対応を解決していました。生成スクリプト内に採用フォント名や必要な太さの組を固定した一覧はありませんでした。
- 参照から求めた`${asset}/${weight}.css`を、styled-systemの`package.json`を基点とする`createRequire`で解決し、重複を除いて並べ替えていました。
- `fontCss()`が作るのは必要なCSSへの`@import`です。CLI実行時に`generated/fonts.css`へ書き出す処理があり、Fontsourceの`@font-face`・`unicode-range`・バイナリを再生成する処理はありませんでした。

**この記録から分かること:** 必要な組の導出元はText Styleであり、アセット対応表や生成スクリプトへ同じ利用判断を重複させていないことを確認できます。アセット対応と利用上の意味は別の情報でした。

**この記録だけでは分からないこと:** ソースコードの読み取りだけでは、生成処理の実行成功やブラウザの描画は保証できません。CSSのパスが解決できることと、対応付けたフォントのデザイン上の妥当性も別です。この読み取りは将来の変更に対する包括的な自動検査ではありません。

**出所:** 上記4ファイルの全文確認。導出・失敗時の動作は[FO-E04](#fo-e04)で別に確認しています。

## FO-E03

**配信するパッケージが依存とCSSエントリーポイントを持つ状態**

**対象時点:** 2026-10-04の実装。

**確認対象:** 3パッケージの`package.json`、[ロックファイル](../../../pnpm-lock.yaml)、[CSSエントリーポイント](../../../packages/styled-system/styles.css)、[生成コマンド](../../../package.json)、[Panda設定](../../../panda.config.ts)、[Preset](../../../packages/design-system/src/preset.ts)、[Storybookの読み込み](../../../.storybook/preview.tsx)。

**観測結果:**

- Fontsource依存は[styled-system](../../../packages/styled-system/package.json)にあり、[React](../../../packages/react/package.json)にはありませんでした。ロックファイルの各ワークスペースの記録も同じ配置でした。
- styled-systemの公開CSSエントリーポイントは、生成されたフォントCSSとPanda CSSを読み込む2行の`@import`でした。React側にCSSエントリーポイントのファイルや公開定義はありませんでした。
- [design-systemパッケージ](../../../packages/design-system/package.json)は`font-assets.ts`を公開していませんでした。styled-systemから`design-system`パッケージへの実行時依存もありませんでした。
- ルートの`design-system:generate`はPandaの生成後にフォント生成スクリプトを実行する定義でした。Panda設定・Presetに`globalFontface`はなく、Storybookはstyled-systemのCSSエントリーポイントを読み込んでいました。
- `generated/fonts.css`はGitの除外対象で、Git管理ファイルとして登録されていませんでした。

**この記録から分かること:** フォントの配信をReact実装から分ける決定と一致する状態でした。生成時に定義を読む関係は、配信パッケージの実行時依存として追加されていませんでした。

**この記録だけでは分からないこと:** この配置の確認は、別フレームワークでの利用、パッケージの公開・取得方式、配布後の動作の検証ではありません。

**出所:** 上記の実装・設定の読み取り、`git check-ignore`とGit管理対象の確認。公開エントリーポイントの解決は[FO-E04](#fo-e04)で検査しています。

## FO-E04

**導出・変更追従・解決失敗と公開境界の再確認**

**検証環境 / 対象時点:** 2026-10-04。冒頭の契約テスト環境で、既存の生成物を読み、生成コマンドを実行せず検査しました。

**入力:** 既存の[フォントテスト](../../../tests/design-system/fonts.test.ts)と[基盤テスト](../../../tests/design-system/foundation.test.ts)を実行しました。

```sh
vp test run --config vitest.design-system.config.ts tests/design-system/fonts.test.ts tests/design-system/foundation.test.ts --reporter verbose
```

**観測結果:** 2ファイル・9テストが成功しました。うちフォントテストは3件で、次を確認しています。

| 検査への入力・操作                                       | 成功した確認                                                                                                                   |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 実際の全Text Style・Token・アセット対応                  | 必要な組と生成関数の出力が一致。解決したCSSに`@font-face`と指定の`font-weight`が存在し、保存済みフォントCSSは`fontCss()`と一致 |
| テスト用Text Styleを1件にし、太さTokenを700から500へ変更 | 対応するFontsource CSSの選択が700から500へ変化                                                                                 |
| Text Styleを空にする / 同じ組を参照するStyleを追加する   | 出力が空になる / 同じCSSを重複して出力しない                                                                                   |
| フォントToken・太さToken・アセット対応をそれぞれ欠かす   | それぞれ例外になる                                                                                                             |
| Dela Gothic Oneの900を要求する                           | 対応CSSを解決できず例外になる                                                                                                  |

太さ変更などの入力は、`body`・`emphasis`というテスト用Tokenと、Zen Kaku Gothic Newのアセット対応を使っています。実際のデザイン定義を書き換えた検証ではありません。テストの期待値としてこの限定入力を明示することと、生成処理へ採用フォント・太さを固定することは別です。

基盤テストでは、`@animic/styled-system/styles.css`が解決でき、`@animic/react/styles.css`と`@animic/design-system/font-assets`が解決できないことも確認しました。9件にはフォント以外の基盤検査を含みます。

**この記録から分かること:** 確認した入力の範囲で、Text Styleの変更への追従、重複除去、必要なCSSの解決失敗の検出、保存済み出力との一致、非公開エントリーポイントの拒否が成立しました。

**この記録だけでは分からないこと:** 空の出力先へのファイル生成やブラウザの読み込みは、この実行では検査していません。要求されない太さが選択されないことは導出結果との一致で確認しており、全アセットの通信量を測った結果ではありません。任意の将来のToken構造やフォントへの対応も保証しません。

**出所:** 上記テストの2026-10-04の実行結果。

## FO-E05

**空の生成先からの再現性**

**対象:** 配置変更後の、空の生成先からの再現性検証。

**入力と手順:** 生成先の各ファイルのSHA-256を記録し、バックアップ後に生成ディレクトリを削除して`vp run design-system:generate`を実行しました。`analysis.json`は比較から除外し、それ以外を生成前後で比較しました。

**観測結果:** PandaのSDK・CSS出力とフォントCSS生成が成功し、生成前後の比較は次の結果でした。

| 項目                              | 結果          |
| --------------------------------- | ------------- |
| 比較したファイル数                | 78            |
| フォントCSS / Native Specを含むか | どちらも含む  |
| 追加 / 欠落 / 内容変更            | いずれもなし  |
| 生成前後の一致                    | `equal: true` |

再現性検証前のフォントCSSは、2026-10-04時点の出力ともバイト単位で一致しました。これは空の生成先からの再現とは別に行った照合です。

**この記録から分かること:** この環境では、フォントCSSを含めて空の生成先から同じ成果物を再現できた記録があります。フォントCSSを再現性の比較から除外していませんでした。

**この記録だけでは分からないこと:** 依存パッケージまで空の状態からインストールした検証ではありません。別OS・依存バージョンや将来の定義変更後の一致は保証しません。`analysis.json`の再現性もこの比較の対象外です。

**出所:** 上記手順による生成結果とSHA-256の比較、フォントCSSのバイト単位の照合。

## FO-E06

**単一CSSエントリーポイントを使うブラウザ検査の記録**

**対象:** 配置変更後のブラウザ検証と、2026-10-04に確認したテスト・ストーリーの検査内容。

**過去の観測:** Chromiumで「単一CSS入口から必要なFontsourceとPanda CSSが読み込まれる」というテストが成功しました。全体は46件成功で、フォント以外の検査も含みます。検証時の依存関係はPlaywright 1.63.0・Storybook 10.6.1です。

**現在の検査内容:** [ブラウザテスト](../../../tests/design-system/browser/foundation.spec.ts)は[Typographyのストーリー](../../../stories/foundations.stories.tsx)を開き、Text Styleから求めたフォント・太さで`document.fonts.load()`を呼び出します。入力文字列は`Animic あにみく`です。返されたFontFaceが存在し、指定の太さで読み込み済みであること、観測したCSS・フォント応答に失敗がないこと、Pandaの背景指定が適用されることを確認します。[Storybook設定](../../../.storybook/preview.tsx)は共通CSSエントリーポイントを読み込んでいます。

**この記録から分かること:** 単一CSSエントリーポイントを使うフォントのブラウザテストの過去の成功と、その入口からの読み込みを検査する現在のコードを確認できます。

**この記録だけでは分からないこと:** 現在のテスト説明を、過去の全アサーションが同一だった証明として扱いません。全Unicode文字の表示、全ブラウザ、実際の画面すべてでの読み込みや視覚品質を保証する結果でもありません。

**出所:** 配置変更後の同名ブラウザテストの実行結果と、上記のテスト・ストーリー・Storybook設定。

## 記録上の限界

- 配置の比較と採否は、設計時の比較に基づく判断です。全候補を実装して性能・保守コストを測った結果ではなく、`globalFontface`の実装失敗やFontsourceの読み込み不良によって担当するパッケージを変えた事例でもありません。
- 互換性を制約にしない決定は、当時APIが未公開・未運用だったという前提によります。公開利用者との互換性問題への対処には一般化できません。
- 契約テスト、空の生成先からの再現、ブラウザへの読み込みは別の検証です。限定した入力・環境での成功を、全フォント・全ブラウザや将来の変更後の成立へ広げることはできません。

現在の仕様と手順は、[設計事例の現行資料](../case-studies/font-ownership.md#現行資料)を参照してください。
